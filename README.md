# 👻 Бюро переселения привидений

Пульт оператора бюро, которое переселяет привидений из старых домов в новые места обитания.
Система подбирает каждому привидению лучшее место, объясняет решение, показывает, кого переселить невозможно и почему,
и предупреждает, если оператор вручную выбрал плохой вариант.

Оформлено как «проклятая Windows 95»: окна со скошенными рамками, WordArt, панель задач с меню «Пуск», синий экран смерти при сбое.
У каждого привидения есть пиксельная аватарка 16×16. Она генерируется из имени, а выражение лица зависит от тревожности:
паникёры дрожат и таращат глаза. Особые условия добавляют детали: очки у любителя книг, капли у любителя сырости.
Анимации отключаются галочкой «Полтергейст» и автоматически при `prefers-reduced-motion`.

## Быстрый старт

Нужен Node.js 18+.

```bash
npm install
npm run dev        # http://localhost:5173
```

```bash
npm test           # 35 тестов ядра подбора и валидации
npm run build      # проверка типов + production-сборка в dist/
npm run preview    # посмотреть собранную версию
```

Деплой автоматический: при каждом пуше в `main` GitHub Actions прогоняет тесты, собирает проект и публикует его на GitHub Pages ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)). Если тесты падают, сайт не обновляется.

Бэкенда и секретов нет. Состояние бюро живёт только в памяти страницы: каждое открытие и обновление — чистое демо, чтобы проверяющий всегда видел один и тот же сценарий. Сохранить свою работу — «Экспорт» в JSON, вернуть — «Импорт».

## Сценарий за 1 минуту

1. Открыть приложение. Демо-бюро уже загружено: 20 новых заявок и 9 мест. Заявки ещё не обработаны.
2. Нажать **«▶ Расселить автоматически»**. Бюро покажет прогресс, а потом итог: сколько расселено и скольким нужно решение оператора.
3. Список **«Требуют решения»** — главная работа оператора. У каждой заявки указана причина и подсказка «Что можно сделать» с кнопкой действия.
4. Выбрать для заявки место вручную в выпадающем списке. Если выбор плохой, появится жёлтое предупреждение с перечнем конкретных проблем. Заявка с местом переходит в **«Расселены»**: там видно место, балл и объяснение, а ручные решения помечены «вручную».
5. Вкладка **Отчёт**: сколько расселено и сколько без места, самые проблемные заявки, перегруженные места.
6. Меню **«Сценарий проверки»** в шапке: готовые состояния «Пустое бюро», «Ручные конфликты», «Импорт битого файла».

## Как работает подбор

Ядро — чистые функции в [`src/engine`](src/engine), UI их только отображает.

**1. Жёсткие условия.** Если нарушено хоть одно, место не подходит:

| Правило | Пример отказа |
|---|---|
| освещённость ≤ 10 − тревожность | «слишком светло: освещённость 8, при тревожности 7 допустимо ≤ 3» |
| \|t места − любимая t\| ≤ 10° | «слишком холодно: 6° при любимых 20°» |
| ограничение места по тревожности | «место не принимает тревожность выше 6» |
| особые условия заявки | нужен чердак / подвал, боится зеркал, нельзя рядом с людьми, нужна тишина, любит сырость (влажность от 60%), любит книги |
| дедлайн не просрочен | «Дедлайн 2026-10-25 уже прошёл» |

**2. Балл** = `100 − 2·|Δt°| − 2·свет − round(шум·тревожность/5)`. Он сравнивает подходящие места между собой, и каждый штраф виден оператору.

**3. Распределение с учётом вместимости.** Новые заявки не занимают мест, пока оператор не нажмёт «Расселить автоматически». Дальше работает жадный алгоритм:
- сначала ручные решения оператора занимают свободные места. Если оператор подтвердил заселение в уже заполненное место, нынешние жильцы остаются, а место становится переполненным — это и есть «перегруз»;
- затем остальные заявки по очереди: раньше дедлайн → меньше подходящих мест → выше тревожность (просроченные идут в конец);
- каждой заявке достаётся место с лучшим баллом среди тех, где ещё есть свободные места.

Номер `#N` на карточке — позиция в этой очереди.

Причины, по которым заявка остаётся без места: `дедлайн просрочен`, `нет подходящего места` (с разбором по каждому месту), `подходящие места заняты`, `в бюро нет мест`.

Почему алгоритм жадный, а не оптимальный: результат легко объяснить оператору («тебя опередила более срочная заявка»). Оптимальное распределение (венгерский алгоритм) — в списке доработок.

«Сегодня» бюро хранится в данных (по умолчанию 2026-10-31) и меняется в шапке. Иначе демо «протухло» бы со временем: через месяц все дедлайны оказались бы просрочены.

## Структура

```
src/
  engine/             ядро без React
    types.ts          модель данных
    rules.ts          все числа формулы и каталог условий
    match.ts          оценка пары «привидение × место» и распределение
    report.ts         финальный отчёт
    validate.ts       валидация форм и импорта
    *.test.ts         тесты (vitest)
  data/demo.ts        демо-данные и сценарии проверки
  data/worklog.ts     содержимое вкладки AI Worklog
  components/         вкладки, формы, аватарки (GhostAvatar), ErrorBoundary
  store.ts            состояние бюро и действия оператора
```
